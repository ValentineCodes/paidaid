# V2.2 fund-on-acceptance — Localnet manual checklist

Prerequisites: `supabase start`, `pnpm sandbox:deploy` (or existing localnet), `NEAR_ESCROW_FUNDING_SIGNER_PRIVATE_KEY` in `apps/web/.env.development`, requester + provider accounts with linked NEAR wallets and balance.

## Happy path

1. Open an **open** request as requester → pending response visible.
2. Tap **Accept this offer** → confirm screen shows provider name and exact amount/asset.
3. Tap **Confirm and fund escrow** → status shows preparing, then wallet prompts.
4. Approve **create escrow** then **fund** in wallet.
5. UI shows verifying states, then **Offer accepted** with **Open engagement**.
6. Refresh request page: response shows **accepted** (not before step 5).
7. Provider receives **response accepted** notification only after step 5.
8. Other pending responses show **rejected** after step 5.

## Wallet / network

- [ ] Wrong wallet connected → error names linked account.
- [ ] Wallet reject on sign → cancel copy, offer still **pending**, **Try acceptance again** works.
- [ ] Insufficient balance → clear error before wallet (or on verify).
- [ ] `NEXT_PUBLIC_NEAR_NETWORK_ID=localnet` matches RPC and escrow contract.

## Recovery

- [ ] After create tx, refresh page → **Continue funding** resumes (no second prepare).
- [ ] Close tab mid-flow, return → in-progress banner + **Continue funding**.
- [ ] Duplicate clicks during busy → no duplicate escrows (button disabled).

## Concurrent acceptance

- [ ] Start accept on offer A → offer B shows blocked message until A completes or fails.

## Unlinked wallet (V1-style users)

- [ ] Requester without linked NEAR → **Link a NEAR wallet** copy, accept disabled.
